# 基础表单

## 场景来源

- 典型基础表单场景：小型目标、活动或配置提交。
- 通用实现协议作为字段映射、依赖字段和提交生命周期参考。

## 业务目标

收集少量结构化信息并直接提交，例如标题、起止时间、目标描述、指标、公开范围。场景重点是清晰校验和一次性提交反馈。

## 场景结构

- 场景标题和说明，解释表单用途。
- 一个主工作区，通常是单张 `Card` 或无框内容区。
- 垂直表单，宽度控制在适合阅读的范围。
- 底部主提交按钮和必要的重置/取消动作。

## 核心交互

- 必填校验和格式校验。
- 百分比、金额、日期范围等字段保持原始值，展示时格式化。
- 依赖字段根据已选项显示，例如公开范围为部分公开时才出现用户选择。
- 提交成功后提示并按业务需要清空、返回上层上下文或进入结果状态。

## 状态与数据流

- `formModel`：所有字段原始值。
- `rules`：本地校验规则。
- `showDependentFields`：由 `computed` 或条件渲染驱动。
- `submitting`：提交状态。
- `submitResult` 或导航目标：提交完成后的反馈路径。

## Sue 组件组合

- `Form`、`FormItem`、`Input`、`TextArea`、`InputNumber`。
- `DatePicker` / `DateRangePicker`、`RadioGroup`、`Select`。
- `Card`、`Button`、`Space`、`message`。
- 使用 `Row` / `Col` 做少量响应式字段组合。

## 复用建议

- 字段依赖用 `computed`、`watch` 或条件 TSX 块实现，不需要复制外部依赖字段封装。
- 当多个表单都有一致提交栏时，可抽本地 SubmitBar。
- 表单 schema 只有在多页共享字段和渲染协议时才值得抽象。

## 反模式

- 为一个简单表单引入大型 schema 引擎。
- 隐藏字段仍保留脏数据并提交。
- 提交中按钮不禁用，造成重复提交。
- 内容宽度过大，长文本字段难以阅读。
