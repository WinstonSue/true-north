# Step 步骤流程

## 场景来源

- 原标准步骤条的业务表达能力：展示流程阶段、当前进度、完成/错误/跳过状态，以及少量可控跳转。
- `Step` / `Steps` 不再作为 `@sue/design-web-vue` 标准组件导出；命中本场景时，在宿主业务内用 Sue 基础组件和本地语义 HTML/CSS 组合实现。

## 业务目标

把多阶段业务的“当前在哪里、已经完成什么、下一步要做什么、哪里存在风险”表达清楚，并让跳转规则服从业务校验，而不是服从视觉组件能力。

## 场景结构

- 步骤轨道：用有序列表、`Flex` 或 `Space` 承载阶段顺序，保留可读的语义结构。
- 步骤节点：展示序号、状态图标、标题、可选副标题、说明和局部进度。
- 当前内容区：wizard/form flow 在步骤下方渲染当前表单、确认页或完成页。
- 状态提示区：风险、错误、禁用、跳过、提交中等状态用 `Alert`、`Tag`、`Badge` 或 `Tooltip` 补充说明。
- 操作区：使用 `Button` 和 `Space` 承载上一步、下一步、提交、重试、返回修改等动作。

## 核心交互

- Wizard / form flow：下一步前只校验当前步骤相关字段；最终提交成功后进入完成态。
- 审批 / 状态跟踪：每个节点展示处理人、时间、意见、状态标签；历史步骤只读，当前待办强调主动作。
- 物流 / 任务进度：按时间或阶段展示到达、处理中、异常、签收等状态，可补充局部 `Progress`。
- 列表行内进度：在表格或列表单行内使用紧凑节点、`Tag`、`Badge` 或小型 `Progress`，不要撑成完整页面流程。
- 风险 / 错误步骤：当前或历史节点失败时展示错误状态、原因、修复动作和可重试入口。
- 已完成步骤：明确完成标识，保留摘要，不重复展示可编辑表单。
- 禁用 / 跳过步骤：禁用要说明原因；跳过要保留 skipped 状态，避免用户误以为已完成。
- 类导航步骤：只有 `canJump` 为真且业务校验允许时才响应点击；禁止点击未来步骤绕过校验。

## 状态与数据流

- `items`：步骤数组，每项包含稳定 `key`、`title`、可选 `subTitle` / `optional`、`description` / `content`、`status`、`disabled`、`percent`、`canJump`。
- `current`：当前步骤索引或 key，由业务推进函数维护，不由点击直接任意改写。
- `status`：建议使用 `wait`、`process`、`finish`、`error`、`skipped`、`disabled`，并允许业务扩展局部标签。
- `disabled`：阻止点击和主要动作，同时通过 `Tooltip` 或说明文本解释原因。
- `percent`：仅用于单步内部进度；整体阶段不要用百分比替代明确步骤。
- `canJump`：由业务规则计算，可跳转不等于可编辑，历史步骤通常只读。
- `onStepClick`：先判断 `disabled`、`canJump` 和校验结果，再触发跳转或提示。
- `loading` / `submitting`：提交、保存、重试期间禁用推进动作，避免重复请求。
- validation-before-next：`next` 必须先完成当前表单、权限、风险确认或异步校验，再推进到下一步。

## Sue 组件组合

- `Flex`、`Space`：组织水平、垂直、紧凑行内步骤布局。
- `Tag`、`Badge`：表达完成、当前、错误、跳过、禁用、审批状态、风险等级。
- `Progress`：表达单步内部进度或列表行内简化进度。
- `Tooltip`：解释禁用、跳过、错误、不可跳转原因。
- `Button`：承载上一步、下一步、提交、重试、返回修改等命令。
- `Alert`：展示跨步骤风险、错误摘要、提交失败、权限不足。
- `Descriptions`：在确认页、审批节点或完成态展示结构化摘要。
- `Divider`：分隔步骤轨道、内容区、确认摘要或历史记录。
- 本地语义 HTML/CSS：优先使用 `ol` / `li`、`aria-current="step"`、`aria-disabled`、按钮语义和项目级样式，不创建运行时 `Step` 组件依赖。

## 复用建议

- 多个业务共享推进协议时，可抽本地 `useStepFlow`，包含 `current`、`next`、`prev`、`goTo`、校验和提交状态。
- 多个页面共享视觉轨道时，可抽项目内 `StepProgress`，但只依赖基础组件和本地 CSS。
- 表单型步骤优先联动 `references/form-step/SCENARIO.md`；完成态和异常态可联动 `references/result/SCENARIO.md`。
- 审批、物流、任务跟踪要保留业务字段，不要把所有节点压成标题和状态两个字段。

## 反模式

- 从 `@sue/design-web-vue`、`@sue/design-web-react` 或 `@sue/design-web-scenarios` 导入名为 `Step`、`Steps`、`StepItem` 或 `StepsProps` 的组件或类型。
- 只生成静态步骤标题，不实现 `current`、状态、禁用、错误和提交中协议。
- 点击任意步骤直接修改 `current`，绕过当前表单校验或业务校验。
- 用完整页面步骤条塞进表格单元格，导致行高、换行和批量扫描体验失控。
- 把已跳过步骤显示成已完成，或把禁用步骤做成可点击但无反馈。
- 失败步骤只变色不提供原因、修复动作或回退路径。
