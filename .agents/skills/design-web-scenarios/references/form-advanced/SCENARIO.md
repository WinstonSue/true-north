# 高级表单

## 场景来源

- 典型高级表单场景：大 payload、多区块、成员明细、一次性提交。
- 通用实现协议作为分区、可编辑表格和底部错误摘要参考。

## 业务目标

承载跨多个业务域的一次性提交，例如仓库、任务、成员、审批配置等。场景要帮助用户在长表单里定位错误并理解提交范围。

## 场景结构

- 顶层表单包住整个提交场景。
- 多个分区卡片：基础信息、任务信息、成员管理等。
- 响应式字段网格，长文本独占行。
- 可编辑表格作为表单明细的一部分。
- 底部粘性提交栏，显示错误数量和提交动作。

## 核心交互

- 提交时校验所有分区。
- 错误摘要可点击并滚动到对应字段。
- 可编辑表格支持新增、编辑、删除行，行 key 稳定。
- 提交成功后提示并按业务进入详情、列表或结果页。

## 状态与数据流

- `formModel`：完整提交 payload。
- `editableRows`：表格明细行，属于 payload 的一部分。
- `errorFields`：校验失败字段集合。
- `submitting`：提交状态。
- `rowKeySeed`：新增行稳定 key。

## Sue 组件组合

- `Form`、`FormItem`、`Card`、`Row`、`Col`。
- `Table` 承载可编辑明细。
- `Popover` 或 `Dropdown` 展示错误摘要。
- `Button`、`Space`、`Alert`、`message`。
- 粘性底栏用本地 CSS 实现，不引入不存在的外部底栏封装。

## 复用建议

- 错误摘要、粘性提交栏、可编辑行状态可在多张高级表单间复用。
- 表单字段和分区强业务定制，优先保留在场景实现内。
- 使用 `code/error-summary.vue.tsx`（Vue）或 `code/error-summary.react.tsx`（React）可快速建立错误摘要结构。

## 反模式

- 把长表单拆成多个互不关联的局部表单，最后手动拼接且缺少整体校验。
- 可编辑表格用数组索引做 key。
- 错误只显示在不可见位置，用户不知道哪里要改。
- 底部提交栏遮挡最后一行字段。
