# Result 结果状态

## 场景来源

- 原 `@sue/design-web-vue` Result 组件的状态展示能力：`success`、`error`、`info`、`warning`、`403`、`404`、`500`。
- `Result` 不再作为标准组件导出；命中本场景时，在宿主业务内用 Sue 基础组件组合实现结果状态。

## 业务目标

在流程完成、操作失败、风险提示、处理中断或异常降级时，给用户一个清晰的状态说明，并提供下一步恢复动作。

## 场景结构

- 状态视觉区：成功、失败、信息、警告用状态图标；403、404、500 可用更大尺寸插图或项目约定插画。
- 标题区：一句话说明当前结果，避免技术细节。
- 副标题区：补充原因、影响范围或下一步建议。
- 操作区：主动作优先，例如返回、重试、查看详情、继续创建、申请权限。
- 内容区：可选，用于展示摘要、错误项、追踪号、帮助信息或后续步骤。

## 核心交互

- `success`：确认操作完成，主动作通常是查看详情、继续创建、返回列表。
- `error`：说明失败原因和可恢复方式，主动作通常是重试、返回修改、联系支持。
- `warning`：提示操作有风险或需确认后续处理，动作要区分继续和取消。
- `info`：用于中性反馈、处理中或状态说明，不要伪装成成功。
- `403`：已登录但无权限时展示，动作包括返回、申请权限、切换账号；未登录应进入认证流程。
- `404`：目标不存在、已删除或链接失效时展示，动作包括回到默认入口、上层上下文或资源集合。
- `500`：关键服务或主数据不可用时展示，动作包括重试、回到默认入口、复制追踪号或联系支持。

## 状态与数据流

- `status`：结果类型，决定语气、视觉强度和默认动作。
- `title` / `subTitle`：由业务状态和接口错误映射生成，不直接暴露后端堆栈。
- `actions`：主次动作列表，由调用方传入具体导航、重试或支持逻辑。
- `details`：可选的业务摘要、错误清单、追踪号、权限说明或帮助链接。
- `loading` / `retrying`：用于禁用重复点击并反馈重试状态。

## Sue 组件组合

- `Flex` 或 `Card` 承载居中或区域内布局，按宿主页面密度决定是否使用边框容器。
- `Button`、`Space` 组织主次动作。
- `Alert` 呈现权限申请说明、风险提示或错误摘要。
- `Descriptions` 展示追踪号、业务摘要、资源信息等结构化详情。
- `Spin` 表示重试中或状态切换中。
- `Empty` 可承载低强度无数据状态；完整流程结果、异常和恢复动作优先使用本场景结构。

## 复用建议

- 抽本地 `ResultState` 只在同一项目里多处重复时进行，避免把场景包当运行时组件库。
- 保持标题、副标题、动作文案由业务传入；场景只约定结构和状态语义。
- 403、404、500 可以共用一个状态壳层，但各自的触发条件和恢复动作必须分开。
- 成功/失败结果适合流程末尾；局部表格、卡片或字段错误优先在原上下文内展示。

## 反模式

- 从 `@sue/design-web-vue`、`@sue/design-web-react` 或 `@sue/design-web-scenarios` 导入不存在的 `Result` 组件。
- 把所有接口错误都跳成 500，导致用户失去当前上下文。
- 403 和未登录混用，导致用户无法通过登录恢复。
- 404 没有返回入口，或返回动作回到同一个缺失状态。
- 将堆栈、SQL、服务名等内部细节直接展示给用户。
- 只有图标和标题，没有可执行的恢复动作。
