## 🚀 快速开始

### 产品经理/设计师
1. 从 **[PRD.md](./PRD.md)** 开始,了解系统整体架构和功能需求
2. 查看各模块的详细文档了解具体功能
3. 参考 TDD.md 中的枚举定义了解数据字典

### 开发者
1. 阅读 **[TDD.md](./TDD.md)** 了解技术栈和架构设计
2. 查看数据模型和枚举定义
3. 参考各模块的 README 了解业务逻辑

### 测试人员
1. 阅读 **[PRD.md](./PRD.md)** 了解业务规则
2. 查看各模块详细文档了解功能点
3. 关注约束规则和状态转换逻辑

## 📝 文档维护

### 文档原则
- **PRD vs TDD**: PRD 关注产品功能和业务,TDD 关注技术实现
- **模块化**: 细节内容分散到各模块子目录
- **及时更新**: 代码变更时同步更新文档
- **清晰引用**: 使用链接建立文档间的关联

### 文档类型说明

| 文档 | 内容侧重 | 目标读者 |
|------|---------|----------|
| PRD.md | 产品功能、业务规则、用户体验 | 产品经理、设计师、测试 |
| TDD.md | 技术架构、数据模型、API设计、枚举定义 | 开发者、架构师 |
| 模块README | 功能详细说明、约束规则、UI设计 | 全部角色 |

### 更新流程
1. 功能变更时更新 PRD.md 和对应模块文档
2. 技术架构变更时更新 TDD.md
3. 新增枚举类型时更新 TDD.md 的枚举章节
4. 数据模型变更时更新 TDD.md 的数据模型章节
