# True North 个人成长系统 - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品定位
True North 个人成长系统是一个综合性的目标管理和任务执行工具,通过**目标(Goal)→任务(Task)→待办(Todo)**三级联动机制,配合**习惯(Habit)**养成系统,帮助用户实现有效的个人成长管理。

### 1.2 系统架构
```
个人成长系统
├── 目标管理 (Goal Management)      # 长期目标规划
├── 任务管理 (Task Management)      # 中期任务分解
├── 待办管理 (Todo Management)      # 日常待办执行
└── 习惯管理 (Habit Management)     # 习惯养成系统
```

### 1.3 核心价值主张
- **目标驱动**: 所有任务和习惯必须关联到明确的目标
- **层级联动**: 目标→任务→待办三级联动,确保执行与目标一致
- **数据驱动**: 完善的数据统计和可视化分析
- **时间约束**: 子级实体的时间范围不能超出父级限制
- **优先级继承**: 子级实体的重要程度不能高于父级

## 2. 核心模块

### 2.1 [目标管理](./goal/README.md)
提供树形结构的目标管理系统,支持目标的创建、编辑、层级管理和进度跟踪。

**核心特性**:
- 树形层级展示,支持无限层级
- 懒加载优化性能,按需加载子目标
- 父子约束机制(时间、重要程度)
- 5种状态、5种类型分类
- 多维度筛选和搜索

详见: [目标管理详细文档](./goal/README.md)

### 2.2 [任务管理](./task/README.md)
任务是连接目标和待办的中间层,负责将长期目标分解为可执行的中期任务。

**核心特性**:
- 二选一关联规则(父任务 OR 目标)
- 时间跟踪功能
- 3种视图(本周/日历/全部)
- 继承父级约束规则

详见: [任务管理详细文档](./task/README.md)

### 2.3 [待办管理](./todo/README.md)
待办事项是最基础的执行单元,提供日常任务的快速创建、管理和追踪。

**核心特性**:
- 5种视图(今日/本周/日历/全部/统计)
- 四象限优先级管理
- 批量操作支持
- 完整的数据统计看板

详见: [待办管理详细文档](./todo/README.md)

### 2.4 [习惯管理](./habit/README.md)
习惯管理通过目标导向的习惯养成,帮助用户建立长期的良好习惯,实现个人成长。

**核心特性**:
- **强制关联目标**(必须至少一个)
- 连续天数跟踪
- 完成率统计
- 习惯日志记录

详见: [习惯管理详细文档](./habit/README.md)

## 3. 业务规则

### 3.1 关联规则

| 实体 | 父级关联 | 约束 |
|------|---------|------|
| 目标 | 可选关联父目标 | - |
| 任务 | 二选一: 父任务或目标 | isSubTask ? parentId : goalId |
| 待办 | 可选关联任务或目标 | - |
| 习惯 | 必须关联至少一个目标 | goals.length >= 1 |

### 3.2 时间约束规则

```
目标时间范围
    ├─ 任务时间范围 ⊆ 目标时间范围
    │   └─ 子任务时间范围 ⊆ 父任务时间范围
    └─ 待办时间 ⊆ 目标时间范围 (如果关联)
```

> [!IMPORTANT]
> 子级实体的时间范围必须在父级范围内,系统会自动验证并限制可选范围。

### 3.3 重要程度约束规则

```
目标重要程度 >= 任务重要程度 >= 子任务重要程度
目标重要程度 >= 待办重要程度 (如果关联)
```

> [!IMPORTANT]
> 子级实体的重要程度不能高于父级,不符合约束的选项会显示为禁用状态。

## 5. 用户体验

### 5.1 交互设计原则

- **简洁高效**: 常用操作一键完成,减少操作步骤
- **即时反馈**: 操作后立即显示加载状态,成功/失败消息提示
- **容错设计**: 重要操作二次确认,错误提示清晰
- **响应式设计**: 适配不同屏幕尺寸,可调整侧边栏宽度

### 5.2 视觉设计

**颜色系统**:
- 重要程度: 灰/绿/蓝/橙/红 (1-5级)
- 难度等级: 灰/绿/蓝/橙/红 (5级)
- 紧急程度: 灰/绿/蓝/橙/红 (5级)
- 状态颜色: 根据业务语义定义

**布局系统**:
- 左侧导航 + 右侧内容
- 抽屉式详情面板
- 卡片式信息展示

详见: [UI设计规范](./common/ui-guidelines.md)

## 9. 注意事项

### 9.1 性能注意事项
1. 大量数据时注意列表渲染性能
2. 树形数据懒加载,避免一次性加载所有节点
3. 合理使用 useCallback 和 useMemo 优化渲染
4. 避免在循环中调用 API

### 9.2 数据一致性
1. 删除目标时需要处理关联的任务和习惯
2. 删除任务时需要处理关联的待办
3. 状态变更需要级联更新相关数据
4. 时间约束变更需要验证子级数据

### 9.3 用户体验
1. 重要操作需要确认提示
2. 加载状态要给予明确反馈
3. 错误信息要清晰易懂
4. 成功操作要有提示反馈

### 9.4 安全性
1. 用户输入需要验证和清洗
2. 敏感操作需要权限验证
3. 数据传输使用加密
4. 防止 XSS 和 CSRF 攻击

## 10. 词汇表

| 术语 | 英文 | 说明 |
|------|------|------|
| 目标 | Goal | 长期的、宏观的成长目标 |
| 任务 | Task | 为实现目标而分解的中期任务 |
| 待办 | Todo | 日常具体的执行事项 |
| 习惯 | Habit | 需要长期坚持的习惯养成 |
| 重要程度 | Importance | 事项的重要性评级 (1-5) |
| 紧急程度 | Urgency | 待办的紧急性评级 (5级) |
| 难度等级 | Difficulty | 目标/习惯的难度评级 (5级) |
| 四象限 | Four Quadrants | 基于重要性和紧急性的任务分类法 |
| 连续天数 | Streak | 习惯持续完成的天数 |
| 时间跟踪 | Time Tracking | 记录任务实际花费的时间 |
